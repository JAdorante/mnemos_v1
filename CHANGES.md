# Web Perceive — a monitor label is not a window title, September 11 2026

Replaying a hosted pilot tester's densest captured day produced four episodes and a 59% attributable-time figure that was entirely false. Of 230 events, 12 carried any anchor; the two episodes that got named rested on coherence 0.04. The cause was one line of capture metadata.

`getDisplayMedia` returns a label for whatever surface the user picked, and `displaySurface` says which kind it is — `browser` (a tab), `window` (one app), or `monitor` (a whole display). Only the first two carry a TITLE. The screen path never asked: it took `track.label` once at `start()`, kept it for the life of the share, and posted it as `?title=`, and `feed_web_frame` filed it as `meta["window"]`. On a whole-screen share that label is the display's name, so every frame of a six-hour day arrived as the same two words — 145 identical "window titles" that looked like signal to everything downstream and were a constant. `context_anchor.title_candidates` rejected 100% of them, which is why the surfaces path scored exactly zero on the one real tester with enough capture to measure.

Three fixes. The label and `displaySurface` are read from the live track on EVERY frame rather than once at start — `surfaceSwitching: 'include'` was already enabled, so a user switching surfaces mid-session silently filed every later frame under the original label. The surface travels to the server alongside the title. And `_web_share_win` demotes a monitor label to `display_label`, leaving `window` empty, because an honest blank is worth more than a field that is always the same lie. Demotion happens only on positive knowledge of a monitor: Firefox has not historically exposed `displaySurface` and an older cached capture page sends none, so silence must not cost a real title.

This makes the pilot's titles honest, not informative — 145 fake titles become zero titles. Getting real ones is a product choice (nudging the picker toward a window or tab share buys titles and a URL at the cost of seeing only one app) and deliberately not made here.

Noted while looking: `vlm.describe` already returns a `title` for every analyzed frame, and `desktop_capture` reads it only to build a summary string. Nothing downstream ever sees it, and 102 of that tester's 230 events carried VLM output. It is model output rather than a verbatim identifier, so it belongs at medium strength and must never mint a binding — but it is a title signal sitting unused on the exact surface the hosted pilot actually has.

Also: `test_capture_dock`'s web-state assertion fails when run after the other capture modules, with or without these changes — the WS connection state in `web_ingest` is module-global and something before it leaves it set.

# CAL — anchor grading, orphaned frames, and two one-line leaks, September 11 2026

Four small fixes, one of which changed what the timeline says more than anything else in Stage 2.

**Tools are evidence, not names.** Replaying a real day produced episodes titled `Claude`, `Firefox` and `console` — every one a tool entity. The timeline was answering "which app was I in", not "what was I working on", which is worse than an empty timeline: a tester reads their browser named back at them once and does not return. Entity kind now grades the anchor. A tool still competes in the evidence field, so switching apps can still lose a frame, but it cannot claim one; `Segmenter._dominant` picks only among nameable anchors. The same flag covers key types — a branch is a detail of a repo rather than a thing you work on, and a `path:` key is nameable only if it names a file or runs deeper than two segments, which is what stops a product route written in a document (`/console/audio-health`) from titling an eighty-minute episode. An episode also now needs its anchor re-evidenced at least twice before it takes its name: one sighting is a guess.

**A child outlived its parent.** A frame suspended on an idle gap could expire while an excursion nested under it was still running, leaving an orphan whose events folded into a stretch that had already ended — the replay reported 201 events inside an 18-minute episode. Descendants of a closing frame are now promoted to roots rather than orphaned (the work did not stop, it just stopped being an interruption of anything), resuming an excursion whose parent did not come back promotes it too, and `episodes.build` refuses to fold a child into a parent whose span does not contain it.

**`self_profile.self_person_id` memoized globally.** A person id means nothing outside the database it came from, so any process opening more than one store — the test suite, a multi-seat host, a replay against a copy — handed the first store's answer to every later one. It surfaced as two passing tests failing only in a full-suite run, with nothing in the traceback pointing at self_profile. The cache is keyed by store now.

**Gmail's `threadId` was being discarded.** `fetch_gmail_headers` already fetches the message resource; line 582 kept `headers` and `ts` and dropped the conversation identity — no extra scope, no body, and stabler than rebuilding a thread from `References` (which is not even requested). It is carried now, with thread ids accumulated per contact, because two people on one thread is co-occurrence a flat message count cannot express. It is NOT yet a CAL `thread:` binding, and the earlier claim that it was "one line away" was wrong: this module deliberately writes one provenance event per source class rather than per message, so there is nothing for a thread key to attach to.

**What this did to the numbers.** Attributable time on the replayed day fell from 86% to 13%, and named episodes from 7 of 9 to 1 of 5. That is the fix working: the labels it removed were a tool, the user's own name, a chat link and a sentence from a PDF. What remains is one genuinely named stretch — Boostrun, 18 minutes — and four honest blanks. Anchor supply, not segmentation, is now the binding constraint.

# CAL Stage 2 — frames, episodes, and replay over captured history, September 11 2026

The timeline is the first thing in this design a user can feel, and the measurement that preceded it said to build it without a model anywhere near it: at 26% per-event coverage, summarizing would produce confidently wrong prose that nothing could debug. So this is segmentation and labelling only, and every label is either earned or blank.

**The segmenter is a pure function over an ordered stream.** `app/services/context/frames.py` never reads the clock and never touches the database — time arrives only as an event's timestamp. That is what makes replaying eleven hours of August and consuming the live bus the same code path, and it is the only reason this logic is testable at all: measured against one real day, the design's rules fire zero times (forced split), once (switch) and twice (freeze-on-idle). Real capture cannot test a state machine; it can only say whether the thresholds feel right. The golden streams in `test_context_frames` are therefore not a convenience, they are where nearly all of this behaviour is exercised, and their shapes are seeded from that day's measured statistics — p50 gap 4 s, median title run one event — rather than from an imagined day of tidy forty-minute blocks.

Three rules carry it, and the one the design leads with is not among them. **Interrupt versus switch**: an excursion that returns nests under its parent and does not cut the episode, so a glance at mail during an hour of work stays part of that hour; only sustained dwell elsewhere switches. **Hysteresis**: two thresholds and a dwell bar, never one threshold, because one flaps and a flapping segmenter shreds an hour into fragments. **Freeze on idle**: with nothing competing, evidence is frozen rather than decayed, so walking away for forty minutes and coming back to the same work resumes it — lunch is not a context switch. The 90-minute forced split is defensive and fires on real data only because frames aggregate across title changes; no single title run came close.

Two bugs the real day exposed that the synthetic streams had not. Evidence accumulated additively, which makes a long incumbency arithmetically undisplaceable — the share thresholds could never fire and the segmenter produced one frame per day and called it success; accumulation now saturates per anchor, the same independence argument the belief layer makes about evidence buckets. And a promoted excursion opened a replacement frame starting before its parent closed, which reads on a timeline as being in two places at once; the child is now promoted in place and its parent ends when the excursion began, which is also the truthful answer.

**Events inherit.** A click carries no identifier and never will; it belongs to whatever the user was doing. `Placement.inherited` records that, `episode_events` keeps it, and on the replayed day 55 of 75 events in the largest episode are inherited. This is the correction that makes ">85% binding coverage per event" a malformed bar rather than a missed one.

**Replay.** `python -m app.services.context.replay --day 2026-08-26` turns a captured day into a timeline in about a second, and `--persist` writes it under a `run_id` so the same day can be re-segmented under different tuning and compared instead of clobbered. New tables `context_frames`, `episodes`, `episode_events`. On the one day in this install's history dense enough to be worth replaying — 287 events over 11 hours — it produces 12 frames and 9 episodes covering every event, with 86% of episode time carrying a real anchor and the rest honestly blank.

**The self node is wrong on this install, and it matters everywhere.** `Mail - Justin Adorante - Outlook` put the user's own name in half their window titles, where it won the evidence field by frequency and named a third of the timeline after the person reading it. Excluding the self person fixes that — except `self_profile.self_person_id` returns person 1, "User 2", because this machine's onboarding profile was never filled in, while the actual human is person 2 with `promotion_state='recognized'`, i.e. modelled as someone else. Anything keyed on self — `link_self`, waiting-on detection, the constellation's `is_self` flag — is pointing at a placeholder here. `SurfaceIndex` therefore identifies self by NAME and store-scoped, from `user_identity` plus the machine's git identity, and deliberately does not call `self_person_id`: that function memoizes a person id in a process-global cache, so in any process that opens more than one store the first store's answer becomes every later store's, which surfaced as two passing tests failing only in a full-suite run.

31 new tests across `test_context_frames` and `test_context_episodes`.

# CAL — one extractor, honest coverage, and the surface path, September 11 2026

Stage 0 put bindings in the ground and measured nothing. Measuring them is what this batch is, and the measurement moved the design more than the design moved the code.

**Two live extractors, reconciled.** `app/services/context/keys.py` and `app/perception/identifiers.py` had grown to overlap by most of their surface — repo slugs, paths, URLs, tickets — with independent stoplists and independent suffix tables. That is the worst available outcome: two graders that disagree, drifting apart on every pilot observation that only one of them learns. `identifiers.py` now owns extraction outright (it is the pilot-hardened one; its comments cite live misfires), and `keys.py` owns the binding GRAMMAR over its output via the new `from_identifiers`. `keys.issues` defers to the same ticket miner instead of carrying a second stoplist, and `registrable` defers to `app/perception/psl` instead of a second suffix table — layering only the PRIVATE suffixes the ICANN section omits, because psl alone collapses `acme.atlassian.net` onto `atlassian.net`, which is the same one-level-too-coarse error the domain stoplist makes.

The grammar immediately earned its keep. A real pitch document reached the miner as the repo slugs `VC/PE`, `ASR/VLM`, `ASR/embeddings`, `payload_hash/expires_at` and `A2/A4` — prose slashes, all of them. The bare-slug scan now carries `src="ocr_slug"` to distinguish it from the host-anchored emission beside it, and the grammar refuses to mint a repository from a slash in prose. Separately, `keys.path` was rooting relative fragments at the reading process's cwd, so the path root word `console` mined out of that same document became `path:<cwd>/console` — a binding that describes the reader rather than the user. It returns None now, and a test pins it.

**The URL key was specified at the wrong granularity.** The registrable domain is right for stoplisting and wrong for identity: `google.com` names no project, but `drive.google.com/document/d/1AbC…` and `claude.ai/chat/<uuid>` are globally unique and externally assigned, which is the definition of an identity key. The stoplist was discarding the identifier sitting in the path. `_trusted_url` deliberately truncates to one path segment because identifier values persist to `quill.db` and full paths would bypass `QUILL_PERCEPTION_URL_FULL` — so the resource is kept as a **digest**, computed where the full URL is still in hand. `url:drive.google.com/document#<16 hex>` binds on first sight and reads back as nothing. Identity without content.

**Stamping, for measurement validity rather than yield.** `identifiers.stamp_event` was called from exactly two producers, both VISION. Clicks — 59% of the stream — carried a window title and a `url_domain` and were never stamped, which made every coverage number measured over that stream uninterpretable. Stamping now happens once in `memory._on_event`, beside the `meeting_session` stamp that was already there, and `stamp_event` early-returns when a producer stamped its own event. Measured cost: 0.06 ms for a click, 0.64 ms at 2 KB of OCR, 7.8 ms at 20 KB.

**The priority inversion.** On a real 494-event corpus, binding coverage was 1/494 — and that one was a link to an online minesweeper. The key grammar is repo/path/branch shaped and fits a Cursor-and-terminal workflow; this stream was Outlook, Drive, Claude and search. But 44% of events carried a window title, and the titles were not empty of meaning: `Boostrun` was already an org in the graph, `Andy Karos` and `Justin Adorante` already people. Nothing resolved, for two fixable reasons — resolution matched the whole segment, so an org inside a search query missed, and it consulted entities only, so the single most frequent segment in the corpus, a person, matched nothing.

New `app/services/context/surfaces.py` resolves title segments against both tables, by equality and by containment, reusing `graph._entity_patterns` / `_person_patterns` and `context_anchor.title_candidates`. It is bind-only: a surface string can never mint a node. Containment needs its own guard, since `graph._STOP_NAMES` covers pronouns only and this graph really does hold entities called `unknown`, `company`, `CEO` and `Boston` — so generic names match by equality but never inside a longer string, and application furniture (`Mail`, `Sign in`, `Google Search`, `Recent`) resolves to nothing at all. Segment coverage went 4.1% → 36.4%, per-event coverage 0.2% → 26.5% (42.7% on input events), with no new capture, no new producer and no model.

**The ship criterion was malformed, not merely unmet.** ">85% binding coverage per event" cannot be satisfied on a stream that is 59% clicks and 79/83 webcam frames, and failing it means nothing: clicks should inherit an anchor from their frame, not each carry one. Measured on the right denominator — runs of one window title, split on a 10-minute gap — the corpus reads 24.2% of blocks and 16.4% of attributable time. Both are *lower* than per-event, because anchored events cluster into a few large blocks while unanchored material fragments into many small ones. Stage 1 is re-targeted rather than cancelled: the instrument was right and the threshold was measuring the wrong thing.

49 new tests across `test_context_surfaces` and additions to `test_context_keys`; suite 3073 tests, 4 known failures, 0 errors.

# Context Association Layer, Stage 0 — bindings and cold-start seeding, September 11 2026

The CAL design's economic claim is that the LLM's job is to *mint* bindings, not to use them: cost scales with the number of novel identifiers, not the number of events, so a user who generates thousands of events a day but a handful of new identifiers a week should be paying almost nothing by week three. None of that compounds unless there is somewhere durable to put a binding, and unless day one starts with some. Stage 0 is those two things and nothing else — no resolver, no frames, no episodes, no behavior change a tester can see.

**Keys.** New `app/services/context/keys.py` extracts context keys deterministically — `repo`, `path`, `file`, `branch`, `domain`, `email`, `thread`, `channel`, `calendar_uid`, `issue`, `bundle` — with no model anywhere in the module and no network. Normalization is the whole point: `git@github.com:Owner/Repo.git`, `ssh://git@github.com:22/Owner/Repo` and `https://token@github.com/owner/repo.git` all land on `repo:github.com/owner/repo`, because the same repository observed in a terminal and in a browser must be one node or the project splits in two. Mail addresses drop display names and plus-tags; threads root on `References[0]` so a four-deep reply keys the same as the message that started it; domains resolve to the registrable domain rather than the hostname (`mail.acme.com` and `acme.com` are one organization), with a bounded static suffix table that keeps `acme.atlassian.net` whole — collapsing that would merge every Jira customer into one node. The table is not the Public Suffix List and says so; `tldextract` drops in without touching a call site.

Two rules do the load-bearing work. **Composition promotes**: `entity_resolver.py` is a terrible key and exists in a hundred repos, but scoped under a bound repo it becomes `file:github.com/owner/repo#app/services/entity_resolver.py`, which is globally unique — and `file()` *refuses* to mint against a weak or absent scope, so a bare filename stays a mention rather than becoming a binding for whatever happened to be open. **Generic keys demote**: `~/Downloads`, `main`, `google.com` and browser bundle ids are real identifiers that carry no project signal, so they drop to supporting tier, where they may reweight a candidate but never propose one and never bind. Consumer mail hosts are generic as *domains* and not as *people* — a personal gmail address identifies someone precisely, while `domain:gmail.com` identifies no organization at all.

**The binding table.** `kg_node_keys` was a name-blocking table: it said a normalized name *might* mean a node, and ambiguity was the point. It keeps doing that, and gains the columns that make it a binding table — `strength`, `key_class`, `origin`, `n_obs`, `seen_days`, `last_seen`, `spread`, `confirmed`, `valid_to` — plus `bind_node_key`, `lookup_binding`, `invalidate_node_key` and `binding_stats`. Writes are idempotent and monotone: re-observing bumps `n_obs`, adds today to `seen_days`, and keeps the strongest claim seen so far, so a user confirmation can never be undone by a later ambient sighting. Identity-class keys bind on first observation — a git remote is assigned by an authority, so there is nothing to disambiguate, only something to learn — while convention-class keys must appear three times across two distinct days, the same discipline `entity_aliases.seen_days` already applies to names. Three sightings in one day is one observation, and the gate says so. Invalidation sets `valid_to` rather than deleting, so events the binding already explained keep their provenance and a later sighting revives the same row. `copy_node_keys` now carries the binding columns through a merge; copying only the key/value pair would have downgraded an inherited `repo:` binding to the 0.5 default and made the winner re-escalate events the loser had already paid to resolve. The partial index lives in `_migrate`, not `_init_schema` — a partial index over a column one `ALTER` away fails the open for every existing install, which is how it was caught.

**Cold start.** Failure mode #10 in the design is the one that bites in a pilot window: on day one nothing is bound, every event is ambiguous, every event escalates, and the first impression is a slow, expensive, wrong system. The fix is not smarter inference — it is noticing that the machine already knows the answers. `onboarding_scan.seed_bindings` mints from git remotes and project roots (`dev_projects` now carries `path`/`remote`/`branch`, which `scan` strips back out so the wizard draft posts exactly the shape it posted before), from the curated bookmark-domain map, and from `person_contact_points` already in the graph. A repo root path is identity-class by composition — it is the mount point of something globally unique — while a folder with only a build marker is a habit and has to prove itself. Contact-point seeding is not gated on `QUILL_ONBOARDING_SCAN`: that flag withholds what the *machine* reveals, and these are addresses the user already gave us. Only strong and medium keys are written, so `figma.com` binds to Figma and `google.com` binds to nothing.

`_bookmark_files` was Windows-only — it read `LOCALAPPDATA` and returned empty everywhere else — so every macOS and Linux tester seeded zero tool bindings. It now knows the Application Support and `~/.config` layouts.

**Measured.** On a synthetic machine at realistic density (22 repos, 8 marker-only project dirs, 30 bookmarked hosts, 40 contacts) seeding writes 128 bindings over 100 nodes in 86 ms, 104 of them usable on day one; the 24 that are not are convention-class paths and branches waiting for a second day. On this developer box — 2 repos, no bookmarks, no ingested contacts — it writes 4. The design's ">200 bindings before the first event" ship criterion is therefore **not met**, and the gap is structural rather than a tuning problem: calendar UIDs and channel IDs are where the remaining volume is, and neither has a node to bind to until episodes exist in Stage 2. 49 new tests across `test_context_keys` and `test_cal_bindings`; the full suite is 3029 tests with the same 4 known failures and 0 errors.

# Router hardening — cutting the infra-driven escalation share, August 31 2026

The week-of-Aug-24 performance brief showed ~42% of cloud escalations were infrastructure, not judgement (local error / cooldown / unavailable), and several of the numbers behind the brief were measurement artifacts. This batch attacks both: fewer paid calls the local tier should have handled, and telemetry that stops lying.

**Local-tier resilience (text).** The Ollama availability probe cached its answer for the life of the process, so Ollama starting a beat after Sparrow pinned every text call of the session to Claude — a negative probe now expires after `QUILL_TEXT_LOCAL_PROBE_TTL_S` (60 s) while a positive one stays cached (later failures re-mark it). A local error used to escalate on the first exception, and a hung daemon taxed *every* call the full 45 s timeout; `model_router` now runs a half-open breaker — one 3 s probe decides between a transient fault (one free local retry) and a dead daemon (marked down so subsequent calls skip the wait, this one escalates). `ollama_text.complete` gained the cheapest rescue of all: a generation that hit `num_predict` (Ollama `done_reason: length` — the thinking monologue or the JSON ran past the budget) re-runs once with double the budget, and a non-truncated unparseable reply is re-asked once with the bad reply plus a correction appended, because at temperature 0 an unchanged prompt just reproduces the failure. Truncations that still escalate are labeled `local_truncated` instead of being buried under `low_confidence`/`parse_failure` — a token-budget problem was hiding inside a judgement metric. The confidence floor is per-task overridable (`QUILL_TEXT_ESCALATE_MIN_CONF_<TASK>`, env-first at call time).

**Local-tier resilience (vision).** The escalate trail showed `local_error`:`local_cooldown` in exact 1:1 lockstep — every one-off 25 s timeout under CPU contention bought a full 120 s window of paid frames, the same penalty as a dead daemon. The cooldown now trips only after `QUILL_VISION_LOCAL_COOLDOWN_ERRORS` (2) *consecutive* errors, doubles per further error, and caps at `QUILL_VISION_LOCAL_COOLDOWN_MAX_S` (480 s); a successful local read resets the streak. The vision probe got the same negative-result TTL as text.

**Tier by reason (text).** Vision has always sent "local was supposed to do this" frames to the cheap tier; text sent every escalation — including a parse failure on a small extract schema — to the task's configured model, and `MODELS` defaulted unknown-and-`extract` tasks to Opus even though `extractor.EXTRACTOR_MODEL` reads the *same* env var with a Haiku default (they now agree: Haiku). Infra-driven escalations (`local_error`, `local_unavailable`, `parse_failure`, `local_truncated`) on ambient tasks now go to `QUILL_TEXT_CHEAP_PARENT_MODEL` (Haiku); chat/plan (user-initiated — quality is the point), high-stakes tasks, low-confidence judgement escalations, and explicit `model=` overrides never downgrade.

**Telemetry that stops lying.** `fact_hygiene` read 0% *structurally*: telemetry fired only on the drop/dedup/review paths, so the numerator could never increment — a rejection counter mislabeled as a pass rate. The insert verdicts (and the empty-text drop) now record, and the metric is registered higher-is-better so the console stops painting it red. Shadow-eval grading calls logged a hardcoded `latency_s=0.0` — 281 rows, the largest zero-latency Claude population in the trail — and now log measured wall time. Thirteen test modules that exercise the router never redirected `model_log`, appending mock rows (fake models, 0 s latency, the entire `grok-4` population) to the developer's real `data/model_calls.jsonl`; each now sandboxes the trail in `setUpModule`, and `cog_telemetry` resolves its path env-first at call time so `QUILL_DATA_DIR`-patching tests are isolated automatically. The escalate histogram had two honesty bugs: the reason chain is first-match, undercounting every gate below the winning branch (`meta.reasons` now records all of them), and `local_kept`/`speculative_local_only`/`parent_failed` rows — 26% of the file — sat unmarked in the reason counts (`stats()` now also reports `escalations`/`by_reason_escalated`).

**Was escalating worth it?** Nothing anywhere compared the local answer to the parent answer — the router's training labels come from scarce human verdicts (11 of 355 rows) and no signal said "the cloud answer was the same". Escalated distill rows now carry `meta.parent_sim` (embedding cosine local-vs-parent, computed only when the embedder is already warm), and `escalate_log.stats()` aggregates it as `parent_agreement` {n, mean_sim, agree_rate at ≥0.8} — the direct "did escalating change the answer?" number, per deploy, that the brief said we couldn't claim yet.

31 new tests in `test_router_hardening` plus additions to `test_vlm_timeout`, `test_escalate_log`, `test_fact_hygiene` and `test_shadow_eval`; the full suite is green against the documented baseline.

# Sparrow pilot readiness — WS-G…K, August 31 2026

The pre-deployment checklist items that are code rather than calendar: clean uninstall and data deletion (a Fix blocker), installer resume for the ~10 GB model download (the other Fix blocker we can automate), and privacy-controls legibility (a Refine bar). The fourth deliverable is `docs/pilot-agreement.md`. Still not automatable and still owed: the fresh-Windows and fresh-Mac install runs on machines we don't own, the Mac dry run, staffing the support channel, and the rehearsed two-machine team-layer demo (which still needs peer-channel TLS).

**WS-G — Erasure.** A tester could take their memory out (WS-B) but not destroy it. The only deletion paths were `POST /perception/erase`, capped at a 90-day window, and an Inno checkbox; `TESTER_SETUP.md` said "delete the folder — all of your data lives in `data\`", which was **wrong**: on this checkout `sessions/` holds 68.6 MB of browser-agent page captures against `data/`'s 107.4 MB, and `desktop_agent/sessions/` holds the action audit. New `app/services/wipe.py` is the single enumeration of all three, and it reads each agent's own `SESSIONS_ROOT` rather than hard-coding a path — both are env-relocatable (`AGENT_DATA_DIR`, `QUILL_DESKTOP_SESSIONS`) and the browser one defaults CWD-relative, so a hard-coded `<install>/sessions` would have reported a clean wipe while leaving the real captures in place. Ordering is load-bearing: capture is stopped (consent revoked **and** pipelines halted — revoking alone leaves the running mic thread writing until restart) and the SQLite handles closed and dropped *before* the walk, because a live writer recreates `quill.db` moments after the delete and an open connection is simply undeletable on Windows, which is where every tester runs. Failures are collected rather than raised, so one locked file cannot strand the other 8 GB, and each run writes a **deletion receipt** — beside the install, never inside the directory it just emptied — carrying per-target byte and file counts, what was kept, and what survived; a test asserts the receipt contains no captured content and no key material. Confirmation is the typed phrase `DELETE MY MEMORY` (the delete button stays `disabled` until it matches, so the destructive click is never the one a stray Enter lands on), and `_guard` refuses the filesystem root, `$HOME`, and any path shallower than three components, because `QUILL_DATA_DIR` is operator-settable and a typo must be refused rather than discovered afterwards. Shipped config (`model_prices.json`, `source_policies.json`, `score_config.json`) survives unless `full=True`: it is byte-identical on every install and holds nothing personal, while deleting it leaves the app running fail-closed rather than fresh — the receipt states this rather than implying an empty directory. Three doors reach the same code: **Privacy controls → Delete everything**, `scripts/uninstall.py` (`uninstall.bat` / `uninstall.command`) which refuses while `/health` answers, and the Inno uninstaller — whose wipe branch now also clears `{app}\sessions` and `{app}\desktop_agent\sessions`, created at *runtime* and therefore never removed by Inno on its own, plus the API key. **Stopping** capture got its own affordance too: a `Stop all` chip on the recording bar and `POST /privacy/stop`, so "make it stop now" is one click on the bar rather than a checkbox inside a settings sheet.

**WS-H — Installer resume.** `scripts/download_models.py` had no retry: one dropped connection at 60% of ~10 GB aborted the step, the installer downgraded it to a warning, and the tester discovered the cost on first run with no progress UI. Every step now retries with doubling backoff and says *resuming* while it does (`huggingface_hub` continues from the `.incomplete` blob, so attempt two costs the remainder — a tester watching a 3 GB bar appear to restart is the moment they give up on the install). A step that exhausts its retries no longer cancels the ones after it; the exit code reports what is still missing and the run continues, so a bad whisper fetch does not also cost the embedder. `--check` probes the caches with `HF_HUB_OFFLINE=1` forced, so an installer or a support call can ask what is left to download without starting one, and VAD is ordered first because something finishing early is what a stalled progress line cannot give you. Both `install.ps1` and `install.command` pass `--retries 5` and now tell the tester that re-running resumes rather than restarts.

**WS-I — Privacy legibility.** The privacy sheet explained what is captured but never what *left*, and the $2/day cap — the number the pilot doc leads with — appeared nowhere in the UI. New `GET /privacy/egress` assembles the answer from records that already exist (the spend ledger, the model-call trail, the usage-ping state, the update check) rather than from a promise, and the sheet renders it as four plain lines: spend against the cap (including calls the cap refused and kept local), cloud calls, the usage ping, the version check. One wording bug was caught by running it against the real trail: `egress_inventory`'s `by_class`/`max_seen` count every call that reached the privacy gate *including the 30 it refused*, so the first draft's "most sensitive class sent" overstated egress on the one page where overstating it costs trust outright — it now says "reached the privacy gate" and leads with the refusal count. A test asserts every key the route reads actually exists in its producer's payload, which is how two renamed keys (`last_ping_at`, `checked_at`) were caught before they silently rendered as "never".

**WS-J — Unattended install + a clean-machine CI gate.** "Test on fresh Windows and Mac machines we don't own" read as un-automatable, and it mostly is — but `windows-latest` / `macos-latest` runners *are* fresh machines we don't own, wiped per run, and nothing was pointing at them. Two things blocked it. Both installers stop dead on the model-account prompt (`Read-Host` / `read -r -p`), so an unattended run does not fail, it **hangs** until the job times out an hour later and looks identical to a slow install the whole time; and the Ollama step pulls ~10 GB plus a winget install nobody asked for. `QUILL_INSTALL_NONINTERACTIVE=1` now takes the account from `QUILL_INVITE_CODE`, else `ANTHROPIC_API_KEY`, else neither — a valid outcome, since the app installs and runs with chat waiting on a key — and a **redirected stdin triggers it on its own**, because a prompt nobody can answer is never the right behaviour and CI should not depend on remembering one env var. `QUILL_INSTALL_SKIP_OLLAMA=1` guards the winget install as well as the pulls: skipping 10 GB of models while still leaving ~1 GB of Ollama on a machine we were told to keep clean is not a skip. Interactive behaviour is unchanged, and a pty-backed test asserts that — a human at a real terminal still gets asked, which is the property a static grep cannot check. `.github/workflows/clean-install.yml` then runs the **real** `install.bat` / `install.command` on a bare runner, asserts the weights are cached with the new offline `--check`, boots `run_all.py --no-browser` and waits for `/health`, and finishes with `scripts/uninstall.py` asserting `quill.db` and the key are gone and a deletion receipt was written. It deliberately omits `--force` there, so a server that failed to shut down is caught by the running-server probe as a real finding rather than papered over. The workflow header enumerates what it cannot prove — SmartScreen and Gatekeeper never fire, runners ship Python so the winget/Homebrew branch stays untested, no TCC prompts, no audio devices, no home-connection download — and a test asserts that list stays in the file, because a green check that quietly stopped covering the double-click is worse than no check. One thing the job found before it ever ran: `install.bat` ended on `pause`, which succeeds regardless, so the launcher always exited 0 and a broken install would have passed the "run the installer" step outright — both batch launchers now capture `ERRORLEVEL` before `pause` and propagate it. Manual gate unchanged: a snapshotted Windows 11 VM and one real Mac.

**WS-K — The desktop build, made real.** The packaged path existed on paper and had never been launched: `release.yml` built the onedir and uploaded it, `iscc` ran nowhere, and nothing ever started the result. Building and running it turned up four defects, each of which would have shipped.

*It could not hear.* The spec carried `excludes=["torch", "tensorflow"]`, but `silero_vad` imports torch at import time **even when loading the ONNX model** — verified directly. A bundle without torch starts fine, serves `/health` fine, and produces no utterances, no memory, and no error explaining why. torch is now bundled (`speechbrain` and `sentence-transformers` need it too), and `Sparrow.exe --self-test` reports per-module load status so this class of bug fails loudly at build time rather than silently on a tester's laptop. The self-test earns its keep immediately: it caught a second one, `speechbrain` missing from the bundle entirely — it discovers its own modules by listing its package directory at import, so a plain hiddenimport is not enough and speaker identification, already a Refine bar on the pilot checklist, was simply absent.

*It wrote into itself.* A packaged install lives in Program Files, which is read-only to the user running it and replaced on upgrade — yet `data/` resolved relative to the working directory, `_cred_path()` resolved `.credentials.env` against `parents[2]` of a service module, and the deletion receipt was written beside `install_root()`. New `app/runtime.py` is the one place that knows a frozen build from a checkout, and seeds `QUILL_DATA_DIR` / `QUILL_CREDENTIALS_FILE` **before** `app.config` freezes its dataclasses, which is the only moment they can be changed. The location is `%LOCALAPPDATA%`, deliberately not Roaming: a memory directory is gigabytes of meeting audio, and on a managed network Roaming would replicate the one thing this product promises never leaves the machine to a corporate file server. The Inno uninstaller was wiping `{userappdata}` — Roaming — and so would have missed the real directory entirely.

*Its first run could not work.* `/bootstrap` shelled out to `[sys.executable, "scripts/download_models.py"]`; frozen, `sys.executable` is `Sparrow.exe`, so that spawns a second copy of the whole app, and `scripts/` is not in the bundle to run anyway. The download logic moved to `app/services/model_fetch.py` so the CLI and the packaged first-run page call the same code by import; `scripts/download_models.py` is now a thin CLI over it. Playwright's Chromium step is skipped in a frozen build and says so, rather than writing a confusing failure into a first-run progress log — the desktop build does not ship the browser agent or the Org Coordinator, because both launch script children the same broken way.

*It opened a terminal.* `console=True` is now `console=False`, the entry point is the new `desktop_app.py` rather than `run_all.py`, and there is an actual shell: a native window via pywebview (Edge WebView2 on Windows) hosting the existing local UI, plus a tray icon with Open / **Stop capture** / Quit — the one control a tester may need in a hurry should not require finding the right browser tab first. Both toolkits degrade rather than crash: no pywebview opens the default browser, no pystray means window-only. A multi-size `.ico` is generated from the wordmark, padded to square first because an ICO encoder stretches a 1024x437 source and smears it at the 16px the taskbar uses.

Size got its own guard rather than a comment. The first successful build was **5.2 GB**, of which 3.3 GB was CUDA — unreachable, since ASR is CTranslate2 int8 and VAD is ONNX. Excluding the modules dropped `triton` (-646 MB) but not the 2.1 GB of `nvidia` binaries, which a module exclude cannot touch; filtering them out of `a.binaries` then built cleanly and **failed at import** with `libtorch_cuda.so: cannot open shared object file`, because `libtorch` links it directly. The wheel is the only lever, so the spec now refuses to build against a CUDA torch and prints the CPU-index command (`QUILL_ALLOW_CUDA_BUILD=1` overrides). Windows PyPI wheels are already CPU-only, so a normal Windows build passes. `release.yml` now runs `--self-test`, launches the bundle and waits for `/health`, prints the bundle size so a multi-gigabyte regression is visible in the log, builds `SparrowSetup.exe` with `iscc`, and triggers on packaging-path PRs rather than only on tags.

Verified on a real build here: the frozen binary self-tests green on all seven critical modules, boots, creates its per-user tree, and answers `/health` with `source_policies.loaded` and `score_v2.config_loaded` both true. **Still owed before anyone outside the team installs it: code signing** — unsigned means SmartScreen on Windows and an un-notarized macOS bundle — and a run on a machine that is not the build machine.

new tests across `test_wipe`, `test_download_models`, `test_unattended_install` and `test_desktop_build`; the full suite is green against the documented baseline.

# Sparrow pilot readiness — WS-A/B/C/D/E/F, August 22-23 2026

Six workstreams for the Sept 8 external installs and the Oct 1 kill-or-continue checkpoint. WS-F landed a day later, once the Mac cohort was confirmed.

**WS-A — Local usage ledger + consented stats send.** The Oct 1 gates (≥8 weekly-active users, ≥25% week-2 retention) were not computable: there was no usage instrumentation anywhere, and the no-telemetry stance means nothing arrives on its own. New `app/services/usage_ledger.py` writes one `usage_daily` row per **UTC** day into the main store — numbers and enum-ish strings only, and structurally so: `bump()` accepts nothing outside `storage.USAGE_COUNTER_COLUMNS`, and the only strings in the table are the day key, a random-UUID install id (never derived from hardware), `__version__`, and `platform.system()`. Counts accumulate in a `Counter` behind one lock and flush on a 60 s timer and at shutdown, so a crash costs ≤60 s of counting and the capture path does no I/O; `bump()` swallows its own exceptions so each of the eleven instrumentation sites is a bare one-liner that cannot fail a request. `active_minutes` dedupes on minute-stamps, so a polling page counts as one minute, not four hundred requests. `metrics_from_rows()` is pure and the date math is pinned hard (install day = day 1, week 2 = days 8–14, `wk2_complete` separates "churned" from "too soon" so the Oct 1 denominator excludes installs that never had the chance). Sharing is three tiers: `POST /usage/report` + a "Send my stats" button writing `data/logs/usage-<install_id>-<day>.json` (default, same interaction shape as the crash zip); an opt-in weekly ping needing **both** `QUILL_USAGE_PING_URL` and a consent flag stored from the Privacy controls, never retried more than once a day, silent-with-log on failure; and the operator side — `scripts/usage_collector.py` plus `scripts/pilot_metrics.py`, which prints the checkpoint table the Oct 1 decision reads. Every payload goes through `crash_report._redact` as defense in depth, and a test asserts it is a byte-for-byte no-op on a compliant payload — if that ever starts differing, a counter has regressed into storing content.

**WS-B — Data export & backup.** `data/` was the only copy of a user's memory with no way out of it. New `app/services/export.py` ships two deliberately different shapes: `POST /export/backup` streams a restorable zip of the data directory, and `POST /export/takeout` streams portable JSONL (events/facts/people/relations + README) that reads without Sparrow, with `?redact=true` for a share-safe variant. Databases are copied with `VACUUM INTO` against the live connection — never a file copy of a hot WAL database — and `-wal`/`-shm` sidecars are excluded, because shipping a stale sidecar beside a checkpointed copy is exactly how a "backup" restores as yesterday's data. Secrets (`.env`, `.credentials.env`, `data/.api_token`, `data/.mcp_token`) never enter either zip, asserted by walking both the namelist and the bytes. Both stream chunk-by-chunk (the 107 GB incident), and the size guard refuses up front — as a clean 400, not a truncated download — when the projected zip would exceed half of free disk. `scripts/restore_backup.py` restores offline: it probes `/health` and refuses while the server is up, validates manifest kind/schema/version, refuses path traversal, and swaps directories atomically so an interrupted restore leaves the old data intact. The manifest counts are read from the *snapshot*, not the live store — filling them from the live store meant a backup taken mid-capture shipped a manifest claiming 307 events beside a database holding 657.

**WS-C — Version check & update banner.** No version constant existed anywhere, which made tester bug reports unattributable to a build. `app/version.py` is now the single source, surfaced in `/health`, the Console footer, the crash-report manifest, the `usage_daily.version` column, and export manifests; the PyInstaller spec reads it textually and stamps `dist/VERSION.txt`, which the Inno script reads, so the installer and the app cannot drift (the hard-coded `MyAppVersion "0.1.0"` is gone). `app/services/update_check.py` GETs a static manifest the operator hosts, on startup and every 24 h, cached to `data/` and exposed at `GET /update/status`. It is a notification, not an updater: no auto-download, no auto-update. The request carries no query params, no install id, and no version header — an unconditional static-file GET, asserted in a test that inspects the outgoing request. Offline/timeout/garbage-JSON is silent-with-log, keeps the last good manifest, and reports `unknown` rather than a false "up to date"; the startup check runs on its own thread so a dead network costs the boot nothing. Semver comparison is `packaging.version` (prereleases sort below their release), and the banner is dismissible per version, with stronger styling and no dismissal below `min_supported`.

**WS-D — API-key onboarding friction (Tier 1 built).** Requiring each tester to create an Anthropic account, add a payment method and mint a key is a hard funnel stop for the persona this pilot is for. Tier 1 ships: the operator pre-creates one revocable workspace key per tester and mints a single-use invite code; `install.bat` offers "I have an invite code" first, and redemption writes the vended key into that machine's own `.credentials.env` through the same `parent_model.save()` the paste path uses — a test asserts the two produce byte-identical credentials. The key stays local and calls go straight to the provider, so the operator's service is never contacted again after install and can be revoked per tester. `scripts/invite_service.py` is the operator half (mint/list/revoke/reissue + a redemption endpoint); the BYO path is untouched and the invite branch does not exist unless `QUILL_INVITE_URL` is set. Tier 2 (hosted proxy) is **designed but deliberately unbuilt** in `docs/key-vending.md`, including the token/budget schema mirroring `spend_cap.py` — it makes operator uptime a dependency for every tester's cloud tier at once, which is the wrong risk during a retention measurement. `TESTER_SETUP.md` is rewritten with the non-BYO path first and now has an explicit "what leaves your machine" table; the $2/day cap is unchanged.

**WS-E — Hybrid search union.** `MemoryEngine.search` was vector-first, with the keyword path running *only* when the ANN index errored — so an exact identifier whose embedding sits far from the query simply never surfaced, silently. The cheap indexed substring/facts-LIKE query now always runs alongside the ANN query; hits are unioned, deduped by `(kind, id)` keeping the max score, and the existing lifecycle filter and `recency_adjusted` ranking apply unchanged. Exact hits enter at `QUILL_SEARCH_EXACT_FLOOR` (0.55) so they clear the noise band without outranking genuinely strong semantic matches — a test documents that honest bound rather than overclaiming it. Keyword contribution is capped at `limit` rows per side so a pathological LIKE cannot flood the pool, and `QUILL_SEARCH_HYBRID=0` restores the old behavior.

**WS-F — macOS tester path.** `install.bat`/`start.bat` are Windows-only, so a Mac cohort had no install path at all — not a degraded one, none. `install.command` is the bash peer of `install.ps1` (venv, requirements, Playwright Chromium, `download_models.py`, and the same invite-code-or-BYO-key branch from WS-D), plus the one step Windows does not need: PortAudio, without which mic capture — the entire point of the macOS build — fails at start with an opaque `OSError`. Ollama stays optional here rather than winget-installed: 10 GB of local models is the tester's decision on their own laptop, and cloud-only works. `start.command` clears the Gatekeeper quarantine on its own folder, which is the difference between a working launch and the "Sparrow is damaged" support call every hand-distributed macOS build generates. `TESTER_SETUP-macos.md` covers the right-click→Open dance, the TCC permission prompts and what declining each one costs, and the BlackHole setup for hearing the remote side of a call — stated as optional, because mic-side capture still produces briefs.

The capture degradation is now *honest* rather than merely guarded. The pipeline already refused non-Windows screen capture and `_resume_source` already turned that into a 503 instead of an ASGI crash, but the Privacy sheet still rendered a Screen checkbox that a Mac tester could tick and watch fail with no explanation. `app/services/capture_support.py` is a pure, platform-parameterised map of what each source can do here, surfaced in `GET /capture/status`; unsupported sources render disabled with the reason, and macOS system audio is offered as "needs setup" with the BlackHole instructions rather than silently not working. The 503 remains the backstop — this is about telling the tester before they click. The existing `macos-latest` CI job now also runs `bash -n` on both launchers (macOS ships bash 3.2, and syntax Linux accepts can still strand the cohort) and the capture-support tests with a real `sys.platform == "darwin"`.

Not automatable and still owed: a dry run on a clean Mac — the Gatekeeper prompt, the microphone TCC grant, and a real meeting with and without BlackHole.

193 new tests across `test_usage_ledger`, `test_usage_metrics`, `test_usage_report`, `test_pilot_metrics`, `test_export`, `test_update_check`, `test_search_hybrid`, `test_invite`, `test_backup_crash` and `test_macos_path`; the full suite is green (2039 passing, with the same pre-existing environment failures as before the change).

# Sparrow KG v2 — post-review revisions (Changes 1–8), July 22 2026

One note up front for the review thread: `kg_nodes`/`kg_node_attrs`/`kg_config` did not yet exist in nexus_v1 (nodes still live in `people`/`entities`; only `kg_predicates` + `kg_evidence` shipped with KG-A), so Changes 1, 2 and 7 were implemented by building the *corrected* design directly against the real node stores rather than patching a flawed one — the flawed versions never shipped.

**Change 1 — Opaque canonical identity keys.** Every person/entity now mints an opaque random 128-bit `canonical_id` (backfilled for existing rows), and normalized/phonetic names are demoted to blocking keys in the new `kg_node_keys` table, where one key may map to many nodes and merges copy (never delete) the loser's keys. Merge identity no longer carries semantics, so an OCR garble like "0penAI" can't poison a node's identity forever.

**Change 2 — NULL-in-PK uniqueness fix.** `kg_node_attrs` ships with a surrogate id plus a `ifnull(valid_from,-1)` expression unique index, because SQLite permits distinct NULLs inside ordinary-table primary keys and would silently duplicate atemporal attributes. The same audit found `kg_evidence`'s dedupe index vulnerable (nullable event_id/quote_hash); a one-shot migration collapses existing duplicates (keeps the highest-weight row, logs each collapse) and swaps in a NULL-folding expression index.

**Change 3 — Temporal-split-first conflict resolution.** Job-change-shaped conflicts (new evidence starting >14 days after the old belief's last sighting, new posterior ≥0.6 on its own) now auto-generate the temporal split — old belief closed at the new one's `valid_from`, superseded, *neither side penalized* — with a pre-filled review proposal instead when the old belief is trusted/protected. The symmetric λ_conflict penalty applies only to genuinely simultaneous conflicts (overlapping evidence windows), and a "both true" adjudication clears the flags and restores posteriors.

**Change 4 — Adjudication logging flywheel.** Every graph decision — evidence confirm/reject, merges, splits, conflict classifications, human and auto alike — writes one `kg_adjudications` row with the frozen feature vector the scorer saw at decision time, turning the console's existing affordances into a free labeling stream for future weight fitting (the fitting job itself is intentionally not built). Source weights moved out of code into a versioned `kg_config` row, so fitted weights can ship without a redeploy; the table is local-only per I-8.

**Change 5 — Lazy, batched posterior recomputation.** Evidence intake now just appends the row and flips `posterior_stale` — no posterior math on the write path, so insert latency is independent of evidence-bag depth. Recompute happens on read (explain/retrieval, with the time-invariant `logit_sum` cached so most reads only re-apply decay) or in the capped `kg_confidence_recal` worker sweep, with a weights-version stamp forcing a full re-scan when the source-weight table changes.

**Change 6 — People queries include the past by default.** Person/org/network retrieval now returns affiliations with `status IN ('active','superseded')` — current ranked first, former annotated with their validity interval ("at Figma 2022–2024") and supersession pointer — because "who do I know at Figma" implicitly includes people who used to work there. Non-people predicates (`uses`, `depends_on`) keep the strict-current default, and explicit time in the question still wins.

**Change 7 — Split detection cut; manual split shipped.** Automated disjoint-cluster split detection is deferred post-PMF: it's the hardest piece of KG-C and its failure mode is fully recoverable by hand because merges are soft and evidence is append-only. In its place, `POST /kg/split` mints a fresh opaque-id node, reassigns user-chosen beliefs (each carrying its evidence bag, mirrored into legacy `relations`), recomputes both sides, and logs the adjudication.

**Change 8 — Dual-write parity diff + cutover gate.** A new `kg_parity_diff` worker (active only in shadow mode) produces nightly node/edge/read parity reports between v1 `relations` and v2 `kg_predicates`, persisted to `kg_parity_reports` and surfaced at `GET /kg/parity` — report-only, never auto-repairing. The M3 read cutover is now an encoded check, not a convention: 7 consecutive reports with zero critical deltas (user-origin edge drift, dangling protected/trusted nodes).

All eight land with acceptance tests in `tests/test_kg_v2_revisions.py`; the architecture doc (§3, §4, §5, §11, §15, §16, §20, §22) was updated in the same changeset so doc and code do not diverge.
